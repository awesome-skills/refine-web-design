# Refine Web Design

Take inspiration from the high visual and experiential quality associated with Awwwards, Webby Awards, and FWA. Aim for distinctive, clear, usable websites. These are not official scoring criteria for this skill; do not guarantee an award or claim an official evaluation.

1. Identify the page's purpose, audience, brand, required content and functionality, technical constraints, and time budget from the conversation. Retain available evidence when details are missing; ask only questions that materially affect design, and do not invent requirements. For review-only requests, report issues and recommendations without editing code, rewriting pages, or publishing. For implementation requests, make changes within the authorized scope.
2. Default to at most 3 rounds of “actual preview → self-review → fix → preview again”. A user-specified iteration limit or time budget takes precedence. Stop when the budget is exhausted, key issues are resolved, or returns diminish substantially. Do not loop indefinitely or use a self-declared “award-winning standard” as acceptance evidence.
3. Each round, actually open the page and inspect desktop and mobile viewports, viewing or capturing screenshots. Also check core interactions, keyboard operation, and relevant performance evidence. Screenshots support visual judgments but cannot replace usability or performance validation. If no browser is available or previewing fails, clearly state what remains unverified and perform only an evidence-based static review; do not pretend to have viewed the page.
4. Review each dimension and record concrete observations:
   - Composition: content hierarchy, alignment, whitespace, density, focal points, and overall rhythm.
   - Typography: brand fit, font sizes and weights, line spacing, line length, and body-text readability.
   - Color consistency: consistent color semantics, clear contrast, coherent states, and decorative colors that do not distract from information.
   - Visual identity: a clear design language grounded in brand and content; avoid generic templates and meaningless decoration.
   - Responsive behavior: desktop and mobile layout, overflow, wrapping, touch targets, and content order.
   - Usability and accessibility: clear navigation and actions, semantic structure, labels, alternative text, keyboard access, focus indicators, and suitable contrast.
   - Interaction: clear feedback, error and empty states, restrained motion, and respect for reduced-motion preferences.
   - Performance: assess loading, resource size, layout shifts, and interaction smoothness using actual evidence; do not fabricate measurements.
5. Prioritize the concrete issues with the greatest impact each round, then recheck fixes and regressions. Respect brand, requirements, and budget. Do not sacrifice readability, accessibility, or performance for spectacle, and do not independently switch stacks, install framework dependencies, or publish the website.
6. At handoff, briefly report completed rounds, major fixes, preview or screenshot evidence, remaining issues, and unverified areas. For review-only requests, provide recommendations ordered by impact. Honestly retain issues that could not be resolved within the budget.
